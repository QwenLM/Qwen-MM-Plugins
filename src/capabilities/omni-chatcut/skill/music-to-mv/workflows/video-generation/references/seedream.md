# Seedream Image Adapter

Select the formal identity-image adapter with `image.provider=seedream`. Its connection lives under
`image_providers.seedream` in the unified model config:

```json
{
  "base_url": "https://ark.cn-beijing.volces.com",
  "api_key_env": "ARK_API_KEY",
  "model": "doubao-seedream-4-5-251128"
}
```

The adapter appends `/api/v3` to this official base URL. Authenticate with the official Ark API key.
Its generation controls remain in the per-run config:

```json
{
  "size": "2K",
  "character_size": "2K",
  "watermark": false,
  "workers": 2,
  "max_attempts": 3
}
```

The adapter sends a synchronous `POST /api/v3/images/generations` request with the cast member's
complete identity-portrait prompt. It requests one URL result, downloads it immediately, and records
the local `.jpg`, request, response, provider name, model, parameters, prompt, and execution signature.
The key is read only from the configured environment variable and is never written to config or state.

Music2MV currently uses this adapter only for text-to-image cast identity portraits. It does not send
reference images, generate scene plates, or create per-shot human keyframes. Scene, wardrobe, action,
blocking, and camera remain text fields in each video request. Keep `watermark=false` for production
identity assets; use `workers` and `max_attempts` to control bounded parallel generation and retry.

Changing between Qwen Image and Seedream changes the image-provider schema and execution signature,
so an identity generated by the other adapter is not silently reused. Wan consumes the downloaded portrait normally. When Seedance is selected, the pipeline skips
identity-image generation and uses only configured Ark image asset IDs; Seedream portraits
are not passed to Seedance. See [seedance.md](seedance.md).
